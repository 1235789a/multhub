# 教程一：从自己的日志核对渠道成本

适用：有合法站点管理权限、愿意主动导出元数据的 API 站长。本工具不改余额、订单或线上路由。

## 先看演示

安装后打开 `/pro/`。240 条合成请求分成两个 Mock 渠道。上方四张卡分别是模型估算、已录入实账、客户收入与已配对毛利。注意覆盖条数：48 条费用有模拟实账时，只能对费用与收入均已知的48条算模拟毛利，不能给整站编一个利润率。

健康分就是成功率百分数，旁边展示样本数、p95总延迟和首Token延迟。报表周期日/周/月使用 UTC。导出诊断为去身份化聚合数据，可交给技术支持；普通 CSV 有请求与渠道标识，不应公开分享。

## 核对 New API 版本和导出格式

本次审计 main 快照 `7d8b91268dab69d7150f345c448b5e250163146a`，最新 Release 查询返回 `v1.0.0-rc.46`。这两个版本标识不是同一件事，不保证 main 等于已发布稳定版。

源码 `router/api-router.go` 中确认：

- `/api/log/`、`/api/log/export`：AdminAuth，未默认连接。
- `/api/log/self`、`/api/log/self/export`：UserAuth，仅自己的日志，导出可被站长关闭。

**重要格式差异**：当前 controller/log.go 的 HTTP 导出实际是 NDJSON，最后一行是 success/error 状态；官方更新日志描述页面导出 CSV。不能把 HTTP NDJSON 直接当 CSV。本版提供的是用户从自己的 New API 界面导出的 CSV → 显式字段映射导入，不请求上述 endpoint，也未实连任何用户站点。

## 导入前准备

1. 切换 GATEWAY_MODE=local，设置自己的租户/令牌，先备份。不要用 demo 保存私人日志。
2. 从你有权限的日志页导出 CSV，确认版本、权限、语言、时间范围。自己核验只有元数据。若只有 NDJSON，先在本地按已核验字段转换，不能直接上传。
3. 用 `/api/prices` 加入该模型的已核验价格快照。一个价格 snapshot 只对应一个 model；输入/输出/缓存单独计价，保存币种、FX时间、出处。系统不提供自动实时行情。
4. 展开页面“导入模板与字段映射”，上传 CSV，在 JSON 中逐列指定真实表头。模板中的列名是 MultiHub 归一化例子，不是所有 New API 版本的真实导出列名。
5. request_id、model_id、timestamp、channel、输入/输出列映射为必需。request_id 必须是稳定、去秘密的计费事件 ID。若源日志没有稳定唯一标识，暂停导入；不能每次生成随机 ID。没有 cache_tokens 的行会标未知，不猜缓存比例。
6. 显式金额列以整数纳单位录入，`actual_cost_nano` 必须来自上游实账；`revenue_nano` 为同币种下游收入。quota 是站点计费单位，不自动转换为 USD。timestamp 需要含时区，建议先统一 ISO UTC。缓存缺失或 Token 缺失会进入未知覆盖统计。费用缺失会留空。
7. 新增 snapshot_id 的列映射到 price_snapshot_id。未提供时默认 manual-v1，需先创建这个精确 ID；演示模板已引用 mock-economy-v1，仅用于演示。
8. 导入相同文件第二次应显示全部重复，费用不增加。相同 ID 不同内容会整批拒绝，先检查是否改了时间、金额或映射。

本版不把 New API 的完整 Prompt、响应、Key、客户身份字段自动带入。未知列被忽略，映射字段进入严格契约。

## 形成一次有边界的判断

对比相同任务、相近输出长度和相同缓存条件的模型；先看模型估算，再对账实际费用。错误率高时导出诊断，检查429/超时/上游5xx的分布。路由建议只能模拟，不会执行。本版没有客户明细分账、税务会计口径、自动告警推送、多节点服务或生产路由执行。
