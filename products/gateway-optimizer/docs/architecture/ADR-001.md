GitHub 连接返回 24 个仓库。已读取/克隆与任务有关的 `1235789a/multhub`、`PriceAI`、`rogerai-api-preview`、`deepseek`。记录 SHA 和文件路径见 `ASSET_AUDIT.json`。

- PriceAI：AGPL-3.0-only；DATA_LICENSE.md 单独限制报价库、采集数据、生产快照、编辑内容和素材。拒绝复制其源码和数据入本产品；没有沿用价格数字。

- deepseek：读取到 README 宣传与配置文字，没有可复用计费实现。未访问或调用其线上 endpoint。

这些检查不等于审计了用户所有私人分支和所有 Drive 文件；未找到 Gateway 代码不证明其他地方绝对不存在。

## 选择

在 MultiHub 仓库独立分支下新增 `products/gateway-optimizer/`；项目自身包管理与发布工件隔离。父站tsconfig的通配扫描会覆盖子目录，因此PR对父tsconfig和ESLint仅添加这个目录的排除项；未改父依赖、路由、业务数据或部署，父站构建未测。两个 Web 入口独立，公共静态资源与 core-api 共用一进程。共享核心依赖为：schema → pricing/usage/health → report/policy/benchmark；adapters 仅负责边界归一化。所有写入经 Store 与租户鉴权。

核心持久化使用 Node 24 内置 SQLite + WAL；单机导入/报表不需要分布式事务。Redis 暂不引入。使用 BigInt 中间算术；公开金额为可安全表示的整数纳美元，累加溢出拒绝；备份保留原币种、价格与汇率快照。

## 与建议栈的差异

没有引入 Next.js、Prisma、核心 PostgreSQL。静态双入口避免重复服务构建，本地 SQLite 降低个人客户安装成本。代价是当前不是多节点 SaaS，不承诺大规模写吞吐和数据库级 RLS。服务端 token 提供基础租户/读写角色隔离；同一操作系统下能读数据库文件的管理员不在该隔离边界中。
